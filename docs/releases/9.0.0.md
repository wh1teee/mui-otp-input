# `@wh1teee/mui-otp-input` 9.0.0

This major release renders the `/shadcn` entry as **one real `<input>`** with
the cells drawn over it, the model of `input-otp` and shadcn/ui. SMS autofill
(`autocomplete="one-time-code"`), keyboard suggestions on iOS and Android,
password managers, WebOTP, screen readers and paste all see a single field,
as current guidance for SMS codes asks. `/base-ui` and the Material UI
component keep their per-cell rendering and public API.

## `/shadcn`: one input

- `InputOTP` renders one transparent `<input>` (`type="text"`, `inputmode` and
  `pattern` from `validationType`, `autocomplete="one-time-code"`) over the
  cells. There is no native `maxlength`: the value pipeline enforces the length,
  so a whole code a keyboard suggestion inserts into a partly filled field
  replaces it instead of being cut. `id`, `name`, `form`, `disabled`,
  `readOnly`, `required`, `enterKeyHint`, `aria-*` and event handlers go to that
  input; `className`, `style` and `data-*` stay on the root.
- `InputOTPSlot` is a drawn cell, hidden from assistive technology. It shows the
  character and sets `data-active`, `data-filled`, `data-fake-caret`,
  `data-invalid` and `data-disabled`; `data-slot="input-otp-slot"` is kept.
  `useInputOTPSlot(index)` returns the same state for custom cells.
- The active cell follows the input's selection: the caret sits after the last
  character, a selected range highlights every selected cell, and clicking or
  tapping a cell moves the caret there, never past the value. A caret blinks in
  the active empty cell and stops blinking under `prefers-reduced-motion`.
- Digits always run left to right, also on right-to-left pages.
- Typing, Backspace/Delete, arrow keys, Home/End, select-all, paste of a whole
  or partial code (spaces and dashes are dropped), one-event autofill, IME
  composition and a controlled value set from outside go through the same
  normalization as before (`validationType`, `transformChar`, `validateChar`,
  `normalizeValue`, `pastePreprocess`). A pasted, autofilled or inserted whole
  code replaces the field wherever the caret was. In pasted text longer than
  the code, the first run of exactly `length` code characters wins
  ("Order 42: code 123456" → `123456`), otherwise the first `length` accepted
  characters; a value a script sets keeps its first `length` characters.
- On a full field a character typed at a collapsed caret overwrites that cell
  (`123456`, Home, `9` → `923456`), also before the browser's `selectionchange`
  arrives; a character past the last cell is ignored, as 8.x `maxlength` did.
- A space or other rejected character typed over a cell changes nothing.
  Delete keeps the caret on the deleted character's cell. The selection is
  left to the IME while it composes. Focus, the active cell and arrow keys
  are tracked inside shadow roots too, and a field mounted into a container
  not yet in the document does not throw.
- `mask` draws dots in the cells only. The input stays `type="text"`, so a
  screen reader still reads the characters.
- Password managers: as in `input-otp`, when a password-manager badge appears
  over this field and there is room, the input grows 40px into a clipped
  gutter past the last cell, so the badge sits beside the cells instead of
  over them.
- `/shadcn` no longer needs `@base-ui/react`. `/shadcn/react-hook-form` is its
  own entry and binds the single input (`field.ref` is the input).

## New

- `onComplete(value)` fires once each time a change makes the value complete:
  not for the value present at mount (controlled or default, also in
  StrictMode), not when a form reset or an RHF `reset()` returns to that mount
  value, not again for the same value, and again after the value passed
  through an incomplete one. Any other complete value set from outside counts:
  a WebOTP fill, and also an RHF `reset(values)` or a restored draft with a
  different complete code. `autoSubmit` submits the owning form with
  `requestSubmit()` on that edge; the form must ignore a second submit while
  one is in flight (Enter or Go right after `autoSubmit`).
- The `ref` of `InputOTP` and `OtpInput` is a handle:
  `clear({ focus?: boolean })`, `focus()`, `root`, `input`.
- `requestWebOtp({ length, signal, transport })` and `isWebOtpSupported()` in
  `/headless` (React-free, `null` where unsupported or on a malformed code;
  only all-digit codes are accepted).
- `useWebOtp({ enabled, length, onCode, transport })` in `/shadcn` and
  `/base-ui` requests the code, calls `onCode` once with a valid code, aborts
  when `enabled` turns false or on unmount, and returns `{ abort, restart }`:
  `abort()` once the code is verified, `restart()` after a resend to listen
  for the new SMS. A no-op on the server and where `OTPCredential` is missing.
- Full-width digits (`１２３`, from a Japanese IME or a paste) become ASCII
  digits in the numeric mode unless `transformChar` is given. This is in the
  shared `/headless` normalization, so `/base-ui` and the Material UI component
  accept them too.

## Migration from 8.x (`/shadcn` only)

`/base-ui`, `/base-ui/react-hook-form`, the root and `/mui` keep their API and
rendering. Their only changes are additive: `useWebOtp` in `/base-ui`, and
full-width digits accepted in the numeric mode (above). `shadcn.css` scopes its
new rules to the single-input field: the root row layout to
`[data-slot='input-otp'][data-single-input]`, and the active, invalid,
disabled and forced-colors cell rules to the drawn `div` cells. A per-cell
`/base-ui` field with the skin renders as in 8.1.0; the new sizing variables
default to the 8.x sizes and change nothing unless set. To keep the per-cell
field, import from `/base-ui` instead of `/shadcn`.

`InputOTPSlot` no longer accepts input attributes. Each removed prop moves to
the root, which forwards it to the single input:

| Removed `InputOTPSlot` prop                                                                                        | Now                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aria-label`, `aria-labelledby`                                                                                    | One name for the field on `InputOTP` (or a `<label htmlFor>` pointing at its `id`); cells have no names.                                                                                        |
| `aria-describedby`, `aria-invalid`, `aria-*`                                                                       | `InputOTP`. `aria-invalid` also sets `data-invalid` on every cell.                                                                                                                              |
| `type` (for example `"password"`)                                                                                  | `mask` on `InputOTP`; the input stays `type="text"` so autofill keeps working. `mask` is visual only: a screen reader still reads the characters.                                               |
| `autoComplete`, `inputMode`, `enterKeyHint`, `id`, `name`, `form`                                                  | `InputOTP`.                                                                                                                                                                                     |
| `disabled`, `readOnly`, `required`, `autoFocus`                                                                    | `InputOTP` (applies to the whole code; there are no per-cell read-only cells).                                                                                                                  |
| `placeholder`                                                                                                      | Draw it in empty cells, for example `[data-slot='input-otp-slot']:not([data-filled])::before`, or with `useInputOTPSlot`.                                                                       |
| `onChange`, `onInput`                                                                                              | `onValueChange(value, details)` on `InputOTP`.                                                                                                                                                  |
| `onKeyDown`, `onKeyUp`, `onPaste`, `onFocus`, `onBlur`, `onMouseDown`, `onClick`, `onCompositionEnd`, other events | `InputOTP` (they receive the input's events).                                                                                                                                                   |
| `ref` (`HTMLInputElement`)                                                                                         | The slot `ref` is now its `<div>`; the input is `inputRef` on `InputOTP` or `ref.current.input`.                                                                                                |
| `render`, `className`/`style` as functions of state                                                                | `className`/`style` are plain values; style state with `data-active`, `data-filled`, `data-fake-caret`, `data-invalid`, `data-disabled`, or render your own cell with `useInputOTPSlot(index)`. |

Other `/shadcn` changes:

- Handlers passed to `InputOTP` compose with the internal ones. For
  `onPaste`, `onMouseDown`, `onClick` and `onKeyDown` the host handler runs
  first and `preventDefault()` skips the internal handling; for
  `onCompositionStart`, `onCompositionEnd`, `onFocus` and `onBlur` the
  internal handling runs first, so the host sees the committed value. React's
  `onBeforeInput` is a synthetic event that does not see deletions and cannot
  hold back the internal edit tracking; to refuse an edit, call
  `details.cancel()` in `onValueChange`.
- The skin sizes cells with `--input-otp-slot-width`, `--input-otp-slot-height`
  and `--input-otp-gap`. Cells never grow past their width and shrink equally
  on a narrow line (six cells fit 320px). The single-input root lays its
  groups and separators out in one row, so a group shrinks to its cells:
  centre the field on the root, not on the group.

- `InputOTP` `ref` is the handle above (was the root `<div>`, now
  `ref.current.root`). `onValueComplete` is replaced by `onComplete(value)`.
  `onValueChange` details are `{ reason, event, cancel(), isCanceled }` with
  reasons `input-change`, `input-clear`, `input-paste` and `imperative`;
  `onValueInvalid` details are `{ reason, event }`. Base UI root-only props
  (`render`, state functions for `className`/`style`) are gone.
- `OtpInput`: `slotAriaLabel` is removed (the label names the input);
  `slotProps` are cell (`<div>`) props; `ref` is the handle.
- `InputOTPSeparator` is hidden from assistive technology (no
  `role="separator"`).
- The `InputOTPRootProps` type is exported from `/base-ui` only.

## Size

Entrypoint budgets (gzip, peers external), measured against 8.1.0:

- `/shadcn`: 3,428 → 6,605 bytes, but it no longer pulls Base UI's OTP Field
  (about 11.5 KB gzip), so an app using only `/shadcn` ships roughly 8.4 KB
  less. Budget 6.9 KB.
- `/shadcn/react-hook-form`: 6,452 bytes (new entry). Budget 6.75 KB.
- `/base-ui`: 3,428 → 3,980 bytes for the added `useWebOtp` and full-width
  digits. Budget 4.05 KB.
- `/base-ui/react-hook-form`: 3,653 → 3,832 bytes; gzip budget unchanged,
  brotli 3.4 → 3.55 KB.
- `/headless`: 801 → 1,084 bytes for `requestWebOtp` and full-width digits.
  Budget 1.1 KB.
- Material UI: 4,455 → 4,502 bytes (index) and 4,888 → 4,934 bytes (React
  Hook Form) for full-width digits; budgets unchanged.

## Known limits

- An 8.x maintenance tag would still publish as npm `latest`: the release
  workflow of the tagged 8.x commit carries `v8.*` and `dist_tag=latest`.
  Protect `v8.*` tags (tag ruleset or a protected publishing environment)
  before cutting one.
- Whether Chrome accepts a new WebOTP request in the same tick as the abort
  of the previous one (`restart()`) is unverified on a device; a rejected
  request resolves to `null` and only that resend is not autofilled.
- `requestWebOtp` accepts digit codes only.
