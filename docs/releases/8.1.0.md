# `@wh1teee/mui-otp-input` 8.1.0

This minor release fixes input-engine defects found in an independent review,
brings the MUI and Base UI renderers closer together, and replaces the
Docusaurus site with interactive documentation.

## Input fixes

- **MUI:** a rejected character no longer erases the slot it was typed into;
  the value is unchanged and only `onInvalid` fires.
- **Both renderers:** `transformChar` runs once per typed, pasted, or
  autofilled character. Stored values (`value`, `defaultValue`) are validated
  by position but no longer transformed again on every render.
- **Base UI:** `validateChar` receives the real slot index for typed and pasted
  characters, and `onValueChange` can cancel a change with `details.cancel()`.
- **MUI:** typing after the character of a filled slot overwrites only that
  slot instead of replacing the rest of the code.
- **MUI:** after `length` shrinks, an uncontrolled field submits only the
  visible characters.
- Slots made read-only through `TextFieldsProps` or `slotProps` keep their
  characters on Backspace, Delete, and paste.
- A form reset cancelled with `preventDefault()` no longer clears the field.
- **MUI:** arrow keys follow the visual order in right-to-left layouts.

## One keyboard contract

- **MUI** now matches the Base UI field: Backspace deletes the slot's
  character (or the previous one when the slot is empty) and steps back, and
  only the active slot is in the tab order, so Tab moves past the whole code.
- Both renderers keep IME composition text in the slot until composition ends
  and commit it once.
- Characters outside the Basic Multilingual Plane, such as emoji, are rejected
  everywhere, so one slot always holds one character.
- The MUI component still reports `onComplete` once on mount for a value that
  starts complete, as the original package did; the Base UI field reports
  completion only for user input.

## Forms and accessibility

- **Base UI form adapter:** React Hook Form marks the field touched only when
  focus leaves the whole field, not when moving between slots.
- **MUI form adapter:** the error message is referenced by every slot through
  `aria-describedby`, not only the first.
- **Base UI:** a slot's own `aria-describedby` is kept next to the field
  description.

## MUI presentation

- Six slots keep whole digits on phone widths: slots may shrink, side padding
  is removed, and the default gap narrows from 20px with the field.
- `TextFieldsProps.type` (for example `"password"`) is respected; `mask` still
  takes precedence.
- A `gap` passed to `MuiOtpInput` replaces the default spacing in MUI 7 and 9.
- `onInvalid` is typed as the field callback rather than intersecting with the
  DOM `invalid` handler.

## Packaging and documentation

- `react` and `react-dom` are optional peers, so `/headless` installs without
  React; every UI entrypoint still requires them.
- Documentation, a configurator with generated code, a React Hook Form example,
  and a migration guide now live in the Next.js site under `site/`. Its type
  check, build, and Playwright/axe suite are part of `pnpm ci:pr`.

Public exports and renderer boundaries are unchanged. The input fixes add
roughly 200–270 bytes gzip per renderer, so entrypoint budgets are re-based on
8.1.0 with about 5% headroom: MUI 4.7 KB, Base UI and shadcn 3.65 KB, MUI +
React Hook Form 5.15 KB gzip. `/headless` and Base UI + React Hook Form keep
their 8.0 ceilings.
