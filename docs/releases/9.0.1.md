# `@wh1teee/mui-otp-input` 9.0.1

The first published 9.x release. `v9.0.0` was tagged but never published: the
release workflow stopped before `npm publish`, at a bundle-size check that
measured the packed tarball differently from the working tree. 9.0.1 is 9.0.0
plus the release-gate fix below; the package code, public API and renderer
behavior are those described in the [9.0.0 notes](./9.0.0.md), including the
migration from 8.x. Install 9.0.1 or later.

## Release gate

- The entrypoint size check now measures the same bytes for the working tree
  and for an extracted tarball. Rolldown keeps `//#region <path>` markers with
  paths relative to the working directory; the tarball, extracted to a
  temporary directory, carried longer paths, so `/headless` measured 1,116
  bytes gzip from the tarball against 1,084 from the tree and failed its
  1,100-byte budget. The markers are bundler bookkeeping a consumer's minifier
  drops, so they are no longer counted. Both measurements now produce the same
  bytes and SHA-256 for every entry.
- `pnpm ci:pr` builds the exact release candidate (`npm pack`) and runs every
  artifact verification the release publishes on — tarball contents, entry
  sizes, the isolated MUI, Base UI, shadcn and React Hook Form consumers and
  the Next.js consumer — against that tarball. Pull requests and the release
  workflow run the same script (`scripts/verify-release-candidate.mjs`); the
  release only adds the tag check and keeps the candidate it publishes.
